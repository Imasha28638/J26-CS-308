# PP1: CloudTrail JSON live inference (PROTO)

This package was built against the **exact two Python training scripts** you uploaded. It uses `featureize_group`, `pad_sequences`, the saved `FEATURES` array, and `WindowLSTM` directly from your existing `src/train_pp1_binary_stack.py`. This avoids accidental feature or model-architecture mismatch.

**All saved models remain trained on controlled synthetic data. This is an engineering prototype, not a validated intrusion detection system.** Predictions on real CloudTrail events have no demonstrated real-world accuracy and must not be reported as verified alerts.

## 3. Export an independent held-out synthetic attack session as CloudTrail JSON

This selects the **first test session with a true injected attack**, ordered by session ID. It does **not** cherry-pick sessions based on whether the model predicted them correctly.

```powershell
py src/export_pp1_heldout_demo.py `
  --events "Data/Synthetic/pp1_experiment/synthetic_experiment_events.csv" `
  --predictions "Data/Experiments/pp1_binary/test_predictions_RESEARCH_PROTO.csv" `
  --kind attack `
  --output "Data/Demo/pp1_heldout_attack_PROTO.json"
```

You should see its session identifier, event count, and injected synthetic event count. The exported file uses standard CloudTrail `{"Records":[...]}` formatting. Its data was constructed for the PP1 synthetic experiment and originates from **held-out test sessions**, not actual AWS CloudTrail.

## 4. Run inference using the saved four models and stack

```powershell
py src/infer_pp1_cloudtrail.py `
  --input "Data/Demo/pp1_heldout_attack_PROTO.json" `
  --models-dir "Data/Experiments/pp1_binary" `
  --output "Data/Experiments/pp1_inference/attack_predictions_PROTO.json" `
  --window-minutes 5
```

Outputs:

- `Data/Experiments/pp1_inference/attack_predictions_PROTO.json`: scored five-minute actor-grouped windows, all four base-model scores and the stacking output.
- `Data/Experiments/pp1_inference/attack_predictions_PROTO_member4_PROTO.json`: **draft** structured Member 2 → Member 4 handoff with anonymized actor identifiers, API summaries and scores. This is **not** an approved group interface specification.

The inferred class is binary only. The scores are uncalibrated synthetic-model outputs, not validated confidence estimates. Attack-category prediction is not implemented.


This Stratus file contains **one event**, so the LSTM has essentially no temporal sequence. More importantly, the trained models have not been validated on Stratus. Results cannot be used to claim real-world attack detection.

For `readOnly` missing in a real log, the tool stops with an explanation rather than silently misclassifying it as a write event. `--on-missing-readonly assume-read` is available for an explicitly non-validated parser demo only and emits a warning.

## 8. Technical notes

- Input: AWS CloudTrail `Records` JSON, a JSON array, single CloudTrail event, or newline-delimited JSON objects. The parser supports JSON keys differing only by case in nested objects.
- Required fields: `eventTime`, `eventName`, `eventSource`, and valid `readOnly` (strict default). `eventTime` must contain a time zone.
- Approximate grouping: hashed `userIdentity.arn` or `principalId`. If not available, hashed source IP, with a warning. No grouping method is guaranteed to identify an actual authenticated user session.
- Default: fixed five-minute UTC-aligned windows. Use the SAME window size as training.
- Tree features and sequence tensors are generated with the **exact code** from the training script. Sequence length is capped at 40 as it was during training.
- Model metadata (provenance, actor hash, event IDs) is excluded from ML feature vectors. Original event IDs are omitted from output unless `--include-event-ids` is used.
- Output payload includes `validation_status = NOT_VALIDATED_FOR_REAL_WORLD_SECURITY_USE`.
- Example/held-out session predictions should be presented as demonstration behavior, not independent external validation on actual AWS logs.

## Troubleshooting

`Missing saved model`: check that both model filenames have `_PROTO` and live in `Data/Experiments/pp1_binary`.

`Model keys ... do not match`: the training artifact is from a different script/version. Do not silently adapt it. Use the exact matching checkpoint and source.

`Saved LSTM dimensions differ`: weights were trained with a different `SEQ_DIM` or `MAX_SEQ`. Reconcile the correct training script first.

`Missing src/train_pp1_binary_stack.py`: do not replace it with an old copy. Keep the script you used to train these models.

`No module named ...`: install the same Python environment dependencies from your earlier `requirements_pp1.txt` (including PyTorch, XGBoost, LightGBM and scikit-learn).

`readOnly missing`: choose a CloudTrail log with complete attributes or explicitly run a nonvalidated demo with `--on-missing-readonly assume-read`.
